Таблица 1. Сущность: Исходный код и Версионирование (Главный диспетчер проекта)


Основной этап — Задача	Что для этого делаем	В каком ресурсе	Как делаем — Команды и инструкции
1.1. Инициализация Git	Создаем локальный репозиторий в корне папки MG/ для контроля изменений.	VS Code (Терминал PowerShell)	Выполнить в корне MG/:
git init
1.2. Игнорирование секретов	Создаем файл .gitignore, чтобы случайно не слить в сеть пароли базы данных и ключи S3 из файлов .env.	VS Code (Редактор)	Создать файл .gitignore в корне и вписать:
* .env
.idea/
/android/app/build/
1.3. Привязка GitHub	Создаем приватный (Private) репозиторий на GitHub и привязываем его к ноутбуку.	GitHub Web + VS Code	git remote add origin https://github.com
1.4. Фиксация правок (Commit)	Сохраняем стабильное состояние кода после чистки мусора и заглушек.	VS Code (Терминал)	git add .
git commit -m "feat: чистка кода, включение обфускации R8"
1.5. Пуш в облако (Push)	Отправляем код на GitHub. Это ваш бэкап кода и мост для деплоя на Timeweb.	VS Code (Терминал)	git branch -M main
git push -u origin main


Таблица 2. Сущность: База данных PostgreSQL (Managed СУБД Timeweb Cloud)


Основной этап — Задача	Что для этого делаем	В каком ресурсе	Как делаем — Команды и инструкции
2.1. Создание кластера	Арендуем изолированную СУБД PostgreSQL 16. Получаем внешний IP, порт и пароль.	Панель Timeweb Cloud	Раздел «Базы данных» ➔ Создать ➔ PostgreSQL 16. Выбираем минимальный тариф для MVP.
2.2. Настройка белого списка	Разрешаем доступ к базе только для вашего домашнего IP и будущего VPS-сервера.	Панель Timeweb Cloud	Раздел СУБД ➔ «Сетевые доступы» ➔ Добавить ваш текущий IP-адрес (узнать на 2ip.ru).
2.3. Подключение к СУБД	Создаем живое соединение с удаленной базой данных для заливки таблиц.	pgAdmin 4 (на ноутбуке)	Нажать Register -> Server. Во вкладке Connection вписать Host (IP из Timeweb), User (postgres) и пароль.
2.4. Проливка схемы таблиц	Создаем все 14 реляционных таблиц, связей и индексов оптимизации.	pgAdmin 4 (Query Tool)	Скопировать текст файла 000001_init_schema.sql, вставить в окно Query Tool и нажать F5 (Execute).
2.5. Контроль бэкапов	Настраиваем глубину хранения автоматических снимков базы.	Панель Timeweb Cloud	Раздел СУБД ➔ «Бэкапы». По умолчанию хостинг делает слепок каждые сутки в 03:00 и хранит 7 дней бесплатно.


Таблица 3. Сущность: Хранилище Медиафайлов S3 (Бакет Timeweb Cloud)


Основной этап — Задача	Что для этого делаем	В каком ресурсе	Как делаем — Команды и инструкции
3.1. Создание бакета	Арендуем бесконечный диск для хранения FullHD фотоотчетов Николая.	Панель Timeweb Cloud	Раздел «Объектное хранилище S3» ➔ Создать бакет. Имя строго латиницей: mg-sfa-storage.
3.2. Выпуск API-ключей	Генерируем токены авторизации для Multipart-моста сервера Go.	Панель Timeweb Cloud	Раздел S3 ➔ «Ключи доступа» ➔ Сгенерировать. Сохраняем себе Access Key ID и Secret Access Key.
3.3. Политика доступов (CORS)	Разрешаем браузеру React напрямую отображать картинки по S3-ссылкам.	Панель Timeweb Cloud	Раздел S3 ➔ Настройки бакета ➔ CORS. Вставить правило:
[{ "AllowedOrigins": ["*"], "AllowedMethods": ["GET"] }]


Таблица 4. Сущность: Виртуальный сервер Linux (Cloud VPS Timeweb)


Основной этап — Задача	Что для этого делаем	В каком ресурсе	Как делаем — Команды и инструкции
4.1. Заказ машины VPS	Арендуем 1 физический сервер на Linux для Docker-контейнеров Go и React.	Панель Timeweb Cloud	Раздел «Облачные серверы» ➔ Создать. Выбрать Ubuntu 24.04 LTS. Тариф: 2 vCPU, 4 ГБ RAM.
4.2. Доступ по SSH ключам	Защищаем сервер от брутфорс-взлома хакерами (запрещаем вход по паролю).	Терминал Windows (PowerShell)	Сгенерировать ключ на ноутбуке: ssh-keygen -t rsa -b 4096. Скопировать публичный ключ в панель Timeweb при создании сервера.
4.3. Терминальное управление	Подключаемся к удаленной консоли Linux сервера для настройки.	VS Code Terminal / PowerShell	Выполнить команду:
ssh root@IP_ВАШЕГО_НОВОГО_СЕРВЕРА
4.4. Установка ядра Docker	Разворачиваем среду выполнения контейнеров на чистой Ubuntu.	Консоль SSH (Удаленный сервер)	Выполнить по очереди внутри SSH сессии:
curl -fsSL https://docker.com -o get-docker.sh
sh get-docker.sh
4.5. Настройка системных логов	Создаем изолированный файл для отслеживания ошибок бэкенда.	Консоль SSH (Удаленный сервер)	mkdir -p /var/log/webtabel/
touch /var/log/webtabel/server.log


Таблица 5. Сущность: Управление доменами и DNS (Кабинет Reg.ru)


Основной этап — Задача	Что для этого делаем	В каком ресурсе	Как делаем — Команды и инструкции
5.1. Привязка веб-панели	Направляем домен .com на веб-интерфейс React внутри VPS.	Личный кабинет Reg.ru	Раздел «DNS-серверы» домена webtabel.com ➔ Изменить A-запись @ и www ➔ Вписать IP вашего Cloud VPS.
5.2. Привязка мобильного API	Направляем домен .ru на пограничник Go-сервера внутри того же VPS.	Личный кабинет Reg.ru	Раздел «DNS-серверы» домена webtabel.ru ➔ Изменить A-запись @ и www ➔ Вписать тот же самый IP Cloud VPS.
5.3. Проверка обновления кэша	Отслеживаем, когда провайдеры увидят смену серверов с Firebase на VPS.	Терминал Windows (на ноутбуке)	Выполнить команду в PowerShell:
nslookup webtabel.com
Должен вернуться IP-адрес вашего нового VPS сервера.


Таблица 6. Сущность: Сервер приложений и Фронтенд (Docker Compose Контур)


Основной этап — Задача	Что для этого делаем	В каком ресурсе	Как делаем — Команды и инструкции
6.1. Набивка боевого .env	Создаем на сервере файл настроек со всеми боевыми паролями от СУБД и S3.	Консоль SSH (Удаленный сервер)	Создать файл nano /app/.env и вписать:
DATABASE_URL=postgres://... (из Таблицы 2)
S3_BUCKET_NAME=mg-sfa-storage
AWS_ACCESS_KEY_ID=... (из Таблицы 3)
6.2. Клонирование репозитория	Выкачиваем чистый код проекта из GitHub прямо на жесткий диск VPS сервера.	Консоль SSH (Удаленный сервер)	Выполнить в корне Linux:
cd / && git clone https://github.com app
6.3. Боевой пуск Docker	Запускаем компиляцию Go, сборку статики React и подъем Nginx одной командой.	Консоль SSH (Удаленный сервер)	Выполнить внутри папки /app:
docker compose up --build -d
6.4. Проверка статуса контейнеров	Убеждаемся, что обе «коробки» успешно запущены и работают без перезапусков.	Консоль SSH (Удаленный сервер)	Выполнить команду:
docker ps
В столбце STATUS должно гореть Up ... seconds/hours.
6.5. Просмотр живых логов	Перехватываем ошибки работы в режиме реального времени.	Консоль SSH (Удаленный сервер)	Выполнить команду непрерывного стриминга лога:
docker compose logs -f backend
